# Изменения

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация версий — [семантическая](https://semver.org/lang/ru/).

## [1.4.2]

### Исправлено
- Окно со сгенерированным паролем показывало только заголовок: высота считалась
  по одной строке, потому что переводы строк в тексте были литеральными `\n`.
  Пароль оставался невидимым, хотя и сохранялся в файл с доступами.
- Сообщения ядра и генераторов systemd (`swapon`, `systemd-ssh-generator`,
  apparmor) пишутся прямо на консоль мимо перенаправлений и ломали разметку
  экрана установки. Теперь на время установки понижается уровень вывода ядра на
  консоль (прежний возвращается при выходе), курсор паркуется в служебной зоне,
  область под строкой состояния очищается, а рамка перерисовывается на каждом
  этапе — экран восстанавливается сам, даже если что-то всё же прорвалось.
- После завершения установки экран очищается до конца, чтобы приглашение
  оболочки начиналось с чистой строки.

## [1.4.1]

### Исправлено
- Значения из файла параметров перебивали ключи командной строки: запуск
  `install.sh -c site.conf --ssl` молча игнорировал `--ssl`, если в файле стояло
  `INSTALL_SSL=no`. Теперь опция всегда важнее файла.
- Проверка значений, попадающих прямо в конфигурацию сервисов (`--search-rate`,
  `--swap-size`, `--fpm-children`, `--fpm-timeout`, `--db-time`, `--ssh-from`,
  `--extra-conf`): раньше мусор доезжал до конфигов и ронял nginx или СУБД.
- `php-fpm` мог называться иначе или отсутствовать — проверка конфигурации пула
  больше не считает это фатальной ошибкой.
- В выводе `wp-autoinstall-check` счётчик нехватки воркеров печатался дважды.

### Изменено
- Адрес репозитория и команды в README приведены к фактическому.
- `uninstall.sh` сохраняет каталог собственных правил сервера в `/root/` перед
  удалением сайта.

## [1.4.0]

### Добавлено
- Настройка пула PHP-FPM по объёму памяти: `pm.max_children` и соседние параметры
  вместо пяти воркеров по умолчанию.
- `request_terminate_timeout` и `slowlog` в пуле — зависший запрос обрывается,
  медленные пишутся в отдельный журнал.
- Настройка СУБД отдельным drop-in конфигом: `max_statement_time` (MariaDB) или
  `max_execution_time` (MySQL), `innodb_buffer_pool_size`, `slow_query_log`.
- Лимит частоты на запросы поиска (`limit_req` только для `?s=`).
- Формат лога nginx с `$request_time`.
- Необязательный кэш готовых страниц `fastcgi_cache`.
- Необязательный файл подкачки, если swap на сервере не настроен.
- `robots.txt` с запретом индексации поиска и админки.
- Каталог `/etc/nginx/wp-autoinstall/ДОМЕН.d/` для собственных правил сервера,
  ключ `--extra-conf` и готовый пример в `extras/`.
- Ограничение SSH одним адресом: `--ssh-from`.
- Команда `wp-autoinstall-check` и запуск проверок в конце установки.

### Исправлено
- При установке второго сайта на тот же сервер затирался `log_format`, на который
  ссылался конфиг первого сайта, и nginx переставал стартовать.

## [1.3.0]

### Добавлено
- Режим `--configure [ФАЙЛ]`: пройти мастер и сохранить ответы, ничего не
  устанавливая. Существующие значения подставляются как ответы по умолчанию —
  параметры правятся пошагово, без текстового редактора.
- Ключ `--save-config ФАЙЛ` и вопрос о сохранении в конце опроса.
- Ключ `--skip-os-check` для apt-совместимых систем, которых скрипт не знает.

### Исправлено
- Скрипт не запускался на Debian: у самого Debian в `/etc/os-release` нет поля
  `ID_LIKE`, оно есть только у производных дистрибутивов.
- В режиме `--yes` значения по умолчанию не проходили проверку — в установку
  могли уехать некорректные данные.
- На сайте, установленном по IP-адресу, почта по умолчанию собиралась в
  заведомо неверный адрес.

## [1.2.0]

### Исправлено
- Пароль с решёткой в файле параметров обрезался: комментарий отсекался по
  первому `#`, теперь только по решётке, перед которой стоит пробел.
- Окно подтверждения параметров имело фиксированную высоту и обрезало последние
  пункты; высота считается по количеству строк.
- В списке компонентов показывались имена переменных вместо названий.

## [1.1.0]

### Добавлено
- Экран установки: рамка с параметрами сверху, прогресс-бар и строка состояния
  снизу, обновляемые на одном месте. Ключ `--plain` возвращает обычный вывод.

## [1.0.0]

Первый выпуск: установка WordPress на Ubuntu одной командой, псевдографический
мастер, выбор веб-сервера и СУБД, автоопределение версии PHP, phpMyAdmin, SSL
Let's Encrypt, UFW и fail2ban.
