# Безопасность

## Что делает скрипт с правами root

Устанавливает пакеты, правит конфигурацию веб-сервера, PHP и СУБД, создаёт базу
данных и пользователя, пишет файлы в `/var/www`. Всё это требует root — запускать
его на машине, которой вы не управляете, не следует.

## Пароли

Скрипт генерирует пароли из `/dev/urandom` и сохраняет их в
`/root/wp-ДОМЕН-credentials.txt` с правами `600`. Файл предназначен для того,
чтобы вы перенесли доступы в менеджер паролей и удалили его с сервера.

Файл параметров (`--save-config`, `--configure`) тоже содержит пароли и тоже
создаётся с правами `600`. В репозиторий его класть нельзя; в `.gitignore`
исключение для `*.conf` уже стоит.

## Как сообщить об уязвимости

Если нашли проблему безопасности, не заводите публичный issue — напишите
владельцу репозитория напрямую через GitHub. Ответ постараюсь дать в течение
недели.

## Что скрипт настраивает для защиты сайта

- запрет выполнения PHP в каталоге загрузок;
- закрытый доступ к `wp-config.php`, `xmlrpc.php` и скрытым файлам;
- `DISALLOW_FILE_EDIT` — редактор кода в админке отключён;
- заголовки `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`;
- отдельный пользователь базы с правами только на свою базу;
- по желанию — UFW и fail2ban, в том числе SSH только с указанного адреса.

Это базовый уровень. Регулярные обновления, бэкапы и разумный выбор плагинов
скрипт за вас не сделает.
